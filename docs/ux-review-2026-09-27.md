# Keepory Historical UX Screenshot Review

Date: 2026-09-27

## Verdict on the supplied captures

**5/10. It looks like a capable beta, but it does not yet feel like a carefully finished consumer product.** The main weakness is prioritization: too much visual weight goes to controls, decoration, and system status; too little goes to finding and using saved content.

Using the demanding design-review lens requested, I would send this back for another pass.

## Scope

This preserves the assessment of the supplied screenshots, not an audit of current `main`. Capture 23 identifies build `main @ 57a4795`; capture 27 shows a different release candidate, so the set is not a verified single-revision capture. The publication branch is based on `a7f6721`. Current code has already resolved the dedicated header selection button concern in finding 1 and the selection-indicator collision in finding 7. Those points are retained below only as historical observations, not outstanding work. Other findings require fresh captures before being treated as current defects.

All 28 supplied screenshots were inspected. The two supplied source sets were byte-identical; one complete set is published in [the screenshot evidence directory](screenshots/ui-ux-scenarios).

This is a screenshot review; interaction quality, actual touch targets, performance, and screen-reader behavior remain unverified. The assessment uses a demanding consumer-product design lens and is not an official Apple review.

## 1. The home screen makes too many things equally important (partially resolved)

[Home screen](screenshots/ui-ux-scenarios/01_home_card_view.png)

**Publication status:** [e66f2bf](https://github.com/stlim0727/stash/commit/e66f2bf95be7e1a87df0d4c0165c2d544e36904c) removed the dedicated selection entry controls. That specific criticism is resolved; the remaining hierarchy observations describe this capture.

Branding, saved count, search, settings, sorting, tags, graph, selection, layout switching, filters, feedback, and adding compete before the user has done anything.

The unlabeled graph and selection icons also require interpretation. A bookmark app should make “find something I saved” immediately obvious.

**Change:** simplify the header, make search prominent, consolidate display options, and move secondary tools into a labeled menu. Keep one dominant add action.

## 2. The cards spend space on the wrong information

[Card view](screenshots/ui-ux-scenarios/01_home_card_view.png) · [List view](screenshots/ui-ux-scenarios/02_home_list_view.png)

Huge branded images get generous space while useful titles are truncated to one line. “Expo — Create amazing apps that r…” is harder to recognize than a complete title, regardless of how attractive the pink rectangle looks.

The list is more useful, but every thumbnail has a blue outline and external-link badge. Repeating that treatment adds noise and can resemble selection.

**Change:** allow two-line titles, reduce preview height, remove decorative thumbnail outlines, and use consistent favicon fallbacks. Make compact browsing the starting point to test.

## 3. The floating feedback button is actively interfering with the product

[Selection](screenshots/ui-ux-scenarios/08_multi_select_selected.png) · [Detail](screenshots/ui-ux-scenarios/17_bookmark_detail_ai.png)

It overlaps the bulk toolbar, tags, and explanatory text. It also competes with the add button. This is a visible obstruction, not a subtle aesthetic disagreement.

**Change:** move feedback into Help or Settings. If this is a beta-only overlay, remove it from production and production review captures.

## 4. The detail screen gives deletion absurd prominence

[Bookmark detail](screenshots/ui-ux-scenarios/16_bookmark_detail_view.png)

“Move to Trash” gets an entire full-width row before the user’s note. Open, Copy, Share, and Preview have almost equal visual weight. “Preview” uses a refresh-shaped icon, making its meaning uncertain.

**Change:** make **Open website** the primary action. Keep sharing secondary, place deletion in an overflow menu, and bring notes and organization higher. If Preview refreshes metadata, label it “Refresh preview.”

## 5. Sync limitations undermine the promise of a personal library

[Sync-dependent detail](screenshots/ui-ux-scenarios/17_bookmark_detail_ai.png) · [Korean home](screenshots/ui-ux-scenarios/28_localized_korean_home.png)

“Tags can be edited once this bookmark has synced” makes basic organization depend on background infrastructure. The Korean home simultaneously explains local storage and shows sync failures. That leaves users wondering whether their bookmarks are safe.

**Change:** allow local tag editing and queue synchronization. Distinguish “Saved on this device” from “Backup failed.” Explain the consequence and offer a specific recovery action. A blue “sync failed” label alone does neither.

## 6. Adding a bookmark has an unclear content model

[Empty form](screenshots/ui-ux-scenarios/14_add_bookmark_empty.png)

The screen says “Add Bookmark,” the URL is optional, the title placeholder refers to a memo, and the large editor says “Memo.” The detail screen calls it “Note.” The empty form’s Save button also looks fully enabled.

**Change:** choose consistent terminology. For links, start with paste URL → preview → save, with optional notes revealed as needed. If standalone notes are supported, make that choice explicit. Make empty-form validity visually clear.

## 7. Selection controls collide with existing controls (resolved)

[Unselected state](screenshots/ui-ux-scenarios/07_multi_select_empty.png)

**Publication status:** [13007a5](https://github.com/stlim0727/stash/commit/13007a5ba6c075dfd253a3546e4df8c83a939c96) moved card selection indicators to the top-left and hides the fallback favicon during selection. The overlap described below is resolved in code and is not an outstanding recommendation.

Empty selection circles sit directly over external-link icons. The user sees two meanings in the same location: open and select.

**Change:** give selection indicators their own predictable position and suppress external-opening affordances during selection. The selected count and blue selected states are otherwise clear.

## 8. The graph has not demonstrated its usefulness

[Graph](screenshots/ui-ux-scenarios/18_knowledge_graph_view.png)

There is substantial empty space, overlapping labels, tiny bookmark nodes, and no visible explanation of the relationships. The interface exposes a visualization without explaining what someone gains from it.

**Change:** establish a concrete task such as finding related bookmarks. Add a short explanation, readable labels, fit-to-content behavior, and a selected-node panel containing useful results. Until then, reduce its prominence on Home.

## 9. The tags browser feels unfinished

[Cloud](screenshots/ui-ux-scenarios/20_tags_browser_cloud.png) · [List](screenshots/ui-ux-scenarios/21_tags_browser_list.png)

The header has no title. “Cloud” and “All” describe different concepts rather than equivalent views. Several cloud colors look faint against the background, and their meaning is unexplained.

**Change:** add “Tags,” use “List / Cloud,” default to the readable list, and make counts and sorting useful. Measure contrast before shipping.

## 10. Error reporting asks the user to become technical support

[Report a problem](screenshots/ui-ux-scenarios/27_report_feedback_screen.png)

The visible experience leads with sign-in requirements and a wall of JSON. Someone already encountering a problem now has another obstacle.

**Change:** lead with “What happened?” and a simple submission path. Put diagnostics behind a collapsed disclosure, explain what will be attached, and provide a clear guest reporting route.

## 11. The visual language and copy need a disciplined cleanup

Oversized rounded containers, heavy shadows, bold labels, emoji, outlined icons, and a solid gear compete across the interface. The result feels assembled from several component styles.

Specific copy issues include “1 items,” “Shared links just show a toast,” and “Notify when AI catches up.” The delete confirmation says “Move to Trash” but its action says “DELETE.”

**Change:** standardize icon weight, corner radii, elevation, typography, and action language. Replace implementation terms with user outcomes—for example, “Show a confirmation after saving.”

## What to keep

The warm neutral background, generally readable text, clear selected-item counts, straightforward sort and language sheets, grouped settings, and explicit irreversible-reset confirmation. These are useful foundations.

## Next design pass

First recapture the current build and reassess the remaining observations. Exclude the resolved selection-control issues above from the implementation backlog. The priorities below reflect the original captures.

Prioritize removing overlaps, fixing save/sync clarity, simplifying Home, improving title visibility, and rebuilding detail-action hierarchy. Graph polish comes after those.

Judge success by whether new users can save, retrieve, organize, and recover a bookmark without explanation.
